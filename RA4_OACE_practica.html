Práctica CE-d: ¿Es de fiar esta web? Detección de fraudes en el acceso web

CE-d · CRÍTICO · 1 sesión de práctica (110 minutos)

1 sesión

Todo el análisis se hace sobre el texto del correo, con el ratón encima del enlace y con la terminal.

2. Objetivos

  • Identificar el host y el dominio real de una URL, distinguiendo subdominios legítimos de dominios falsos camuflados.
  • Comprobar los medios de seguridad de una web: HTTPS, certificado digital válido, cookies y cierre de sesión.
  • Reconocer las señales de fraude en un correo o SMS de phishing (remitente, urgencia, enlace real, adjuntos peligrosos, petición de datos).
  • Verificar el cifrado y el certificado también desde la terminal, sin abrir la web sospechosa.
  • Aplicar medidas de contención y reporte ante un intento de fraude.
  • Documentar el análisis en un informe técnico claro, apto para un compañero no técnico.

3. Práctica guiada — BÁSICO Guiado

Trabaja con el navegador abierto y con una terminal (Windows: Símbolo del sistema; Linux: Terminal). Anota todo lo que observes.

Paso 1. Analiza las URLs a mano, sin abrir ninguna.

Lee cada dirección y sepárala en partes. Recuerda la regla: el host es lo que va entre las barras dobles y la primera barra simple; el dominio real son las dos últimas etiquetas del host (tres si el sufijo es compuesto, como .gob.es o .com.es).

N.ºURL
1https://www.correos.es/seguimiento/4832910XZ
2http://correos-espana.info/pago/4832910XZ
3https://www.correos.es.verificacion-segura.xyz/login
4https://sede.agenciatributaria.gob.es/Sede/cita_previa.html
5https://login.bbva.es.websegura.top/accessos

Rellena para cada URL: host, dominio real, protocolo (HTTP o HTTPS) y veredicto (legítima, sospechosa o fraudulenta). Justifica las dos últimas en una frase cada una.

Verificación del paso 1: debes haber escrito que la URL 3 pertenece al dominio verificacion-segura.xyz y no a correos.es, aunque el texto correos.es aparezca dentro. Si has puesto «Correos», el paso está mal.

Paso 2. Busca las señales de fraude en los dos correos.

Sin abrir nada, revisa uno por uno y anota la evidencia. Fíjate sobre todo en:

  • Remitente: compara el dominio que va después de la arroba con el dominio oficial. Correo A: correos-espana.info. Correo B: correos.es.verificacion-segura.xyz. Ninguno de los dos es correos.es.
  • Enlace real frente a enlace visible: en el correo A el texto dice una dirección y el destino real es otra. En Firefox puedes verlo pasando el ratón por encima sin hacer clic, o con clic derecho y «Copiar dirección del enlace» y pegarlo en un bloc de notas.
  • Urgencia y miedo: «24 horas», «será devuelto», «antes del 30/06». Es la presión típica del phishing.
  • Petición de datos sensibles: dirección, teléfono y, sobre todo, datos de tarjeta. Una empresa legítima no pide la tarjeta por correo.
  • Adjunto peligroso: Etiqueta_4832910XZ.html. Un HTML adjunto puede contener un formulario falso o código que descarga malware.
  • Falta de cifrado: el enlace real del correo A empieza por http://, sin la «s».

Clasifica: ¿cuál de los dos correos es un fraude evidente y cuál está diseñado para engañar a alguien con más experiencia? Escribe al menos cuatro señales de alarma, indicando en qué correo aparecen.

Verificación del paso 2: has detectado que el correo B es más peligroso porque su enlace sí usa HTTPS, y aun así el dominio real no es correos.es. El candado no garantiza la identidad de la web.

Paso 3. Comprueba el cifrado y el certificado de la web legítima desde el navegador.

  1. Abre https://www.correos.es (esta sí es la web oficial).
  2. Pulsa el candado que aparece a la izquierda de la barra de direcciones.
  3. Entra en «Conexión segura» y después en «Más información» y «Ver certificado».
  4. Apunta: emisor (la autoridad de certificación), asunto o nombre común, fecha de alta y fecha de caducidad, y los nombres alternativos (SAN) que cubre.

Registra los datos del certificado y responde: ¿el nombre del certificado coincide exactamente con el dominio que estás visitando? ¿La fecha de caducidad está en el futuro? ¿Quién lo emite?

Verificación del paso 3: el certificado debe estar emitido por una autoridad de confianza, estar vigente y contener correos.es en el titular o en los nombres alternativos. Si el nombre no coincide, el navegador muestra un aviso de «conexión no segura» aunque la web se vea igual.

Paso 4. Comprueba lo mismo desde la terminal, sin abrir la web sospechosa.

Windows (Símbolo del sistema)

curl -I https://www.correos.es

  • curl: cliente de transferencia que pide una dirección y muestra la respuesta.
  • -I (letra i mayúscula): pide solo las cabeceras, no descarga el contenido de la página. Es la forma segura de «mirar» una web sin abrirla.

Linux (Terminal)

curl -I https://www.correos.es

echo | openssl s_client -connect www.correos.es:443 -servername www.correos.es

  • openssl s_client: abre una conexión TLS y nos muestra el certificado del servidor.
  • -connect: indica host y puerto; el 443 es el puerto estándar de HTTPS.
  • -servername: dice al servidor qué dominio pedimos (SNI); imprescindible cuando un servidor aloja varias webs.
  • Para salir, pulsa Ctrl + C.

Después, comprueba a qué IP resuelve el dominio oficial y qué documentación pública existe sobre el dominio falso:

nslookup www.correos.es — consulta el DNS y devuelve una o varias direcciones IP.

nslookup correos-espana.info — en el aula resolverá a 192.168.20.10 porque es una réplica; en internet real, un dominio de este tipo suele estar registrado hace pocos días.

Copia la primera línea de respuesta de curl -I (por ejemplo, el código de estado) y la línea del certificado donde aparece el titular. Explica con tus palabras qué significa el código 200 y qué significaría un error de certificado.

Verificación del paso 4: en la respuesta debe aparecer HTTP/2 200 o HTTP/1.1 200 OK y ningún mensaje del tipo «SSL certificate problem». Si aparece ese error, el certificado no es válido para ese dominio y la web no es de fiar.

Paso 5. Revisa las cookies y la sesión.

  1. Con la web oficial abierta, pulsa el candado y entra en «Cookies y datos del sitio».
  2. Identifica al menos dos cookies y para qué sirven (sesión, idioma, preferencias).
  3. Comprueba que las cookies de sesión del banco o de la sede electrónica son HttpOnly y Secure.
  4. Cierra la sesión con el botón «Salir» de la web y comprueba que al volver atrás ya no estás dentro.

¿Por qué es peligroso aceptar todas las cookies de un sitio desconocido? ¿Qué diferencia hay entre cerrar la pestaña y cerrar la sesión?

Verificación del paso 5: tras pulsar «Salir», al recargar la página debe aparecer el formulario de acceso otra vez. Si sigues dentro, la sesión no se ha cerrado correctamente.

Paso 6. Refuerza la cuenta: contraseña robusta y doble factor (2FA).

  • Una contraseña robusta tiene 12 caracteres o más, mayúsculas, minúsculas, números y símbolos, y no contiene datos personales ni palabras del diccionario.
  • Mejor aún: una frase de paso de cuatro palabras sin relación entre sí (por ejemplo, una combinación inventada por ti y distinta para cada servicio).
  • El 2FA añade un segundo comprobante: un código de 6 dígitos en el móvil, una aplicación autenticadora o una llave física. Aunque te roben la contraseña, no pueden entrar.

Crea y escribe una política de contraseñas en cinco normas para la plantilla de Almenara. Incluye una norma sobre el gestor de contraseñas y otra sobre el 2FA.

Verificación del paso 6: tus normas deben prohibir reutilizar contraseñas entre servicios, prohibir apuntarlas en un papel pegado al monitor y exigir 2FA en el correo corporativo y en la banca.

Paso 7. Aplica el protocolo de actuación y reporta el fraude.

  1. No abrir ningún enlace ni adjunto del correo.
  2. No reenviar el mensaje a compañeros: multiplica el riesgo.
  3. Marcar el correo como phishing o spam desde el cliente de correo.
  4. Enviar el mensaje completo, como adjunto (no reenviado), a seguridad@almenara.es.
  5. Si alguien ya ha introducido la contraseña: cambiarla desde otro equipo limpio, activar 2FA y avisar a informática de inmediato.
  6. Si se ha descargado o ejecutado un archivo: desconectar el equipo de la red (cable fuera o wifi apagada), no borrar nada y avisar a soporte.

Redacta el informe que enviarías a tu responsable: qué se ha recibido, qué se ha comprobado, qué se ha decidido y qué medidas se proponen para toda la plantilla. Extensión mínima: 10 líneas.

Verificación del paso 7: el informe debe poder leerlo una persona no técnica y debe dejar claro que no se ha abierto ningún enlace y que el correo se ha reportado como adjunto.

4. Variación — MEDIO Adaptación

Dos días después llegan dos casos nuevos al buzón de soporte. Ahora no te damos la lista de pasos: debes reutilizar el procedimiento anterior y adaptarlo. Además, uno de los casos no es un fraude.

CasoDescripción
Caso 1 — Smishing SMS al móvil de empresa desde el número 615 22 33 44: «Almenara: su factura 2024/1187 no se ha podido cobrar. Actualice el método de pago en https://almenara.es.facturacion-online.click/pagar antes del 48 h».
Caso 2 — Quishing Cartel pegado en la puerta del almacén: «Descargue la nueva app de fichajes escaneando este código QR». El QR lleva a http://almenara-app.apk/instalar. Al escanearlo, el móvil avisa de que la web no es segura.
Caso 3 — Falso positivo El navegador avisa «Conexión no segura» en https://intranet.almenara.local, el servidor web interno del aula (192.168.20.10). Los compañeros entran sin problema desde otros equipos. El certificado está emitido por una autoridad pública, pero su titular es web.aula.local.

Para cada caso: (a) escribe el host y el dominio real del enlace; (b) indica qué medio de seguridad falla o qué señal de fraude aparece; (c) decide la actuación inmediata; (d) redacta el aviso de una línea que darías a la plantilla.

El caso 3 es un falso positivo. Explica por qué el navegador se queja aunque el certificado sea auténtico y qué habría que hacer para que deje de avisar (sin desactivar la comprobación de certificados en todos los equipos).

Pistas para la variación: en el caso 1 el dominio real es facturacion-online.click; en el caso 2 hay doble señal (HTTP sin cifrado y un dominio terminado en .apk, la extensión de las aplicaciones de Android); en el caso 3 el certificado es válido para web.aula.local pero no para intranet.almenara.local, y la solución es instalar una autoridad de certificación interna (CA propia) o emitir un certificado con el nombre correcto.

Windows

netsh winhttp reset proxy — devuelve la configuración de proxy del sistema a «sin proxy»; elimina el desvío del tráfico.

type C:\Windows\System32\drivers\etc\hosts — muestra el archivo de resolución local; cualquier línea que no empiece por almohadilla es sospechosa.

notepad C:\Windows\System32\drivers\etc\hosts — edítalo como administrador y borra las líneas falsas.

ipconfig /flushdns — vacía la caché DNS del equipo (/flushdns) para que no siga usando respuestas envenenadas.

Linux

cat /etc/hosts — equivalente al type de Windows.

sudo nano /etc/hosts — edición del archivo con permisos de administrador (sudo).

resolvectl status — muestra los servidores DNS en uso; delata DNS añadidos a mano.

sudo resolvectl flush-caches — vacía la caché de resolución de nombres.

sudo rm -rf ~/.mozilla/firefox/*.default*/extensions — elimina las extensiones del perfil de Firefox (en un caso real, mejor desinstalarlas desde about:addons).

9. Checklist de entrega

⚠ CRITERIO DE EVALUACIÓN CRÍTICO

Para superar el CE-d el alumno debe demostrar obligatoriamente y sin ayuda que:

1. Identifica correctamente el dominio real de una URL, incluso cuando el nombre legítimo aparece como subdominio o dentro del texto del enlace (por ejemplo, www.correos.es.verificacion-segura.xyz pertenece a verificacion-segura.xyz).

2. Comprueba los medios de seguridad de un acceso web: presencia de HTTPS, validez, vigencia y titular del certificado digital, y comportamiento de las cookies de sesión.

3. Reconoce un fraude de tipo phishing, smishing o quishing enumerando al menos cuatro señales de alarma, y entiende que HTTPS no equivale a sitio legítimo.

4. Aplica el protocolo de actuación sin abrir enlaces ni adjuntos sospechosos, con contención inmediata del equipo afectado y reporte del correo al buzón de seguridad.

5. Justifica con lenguaje técnico y comprensible las decisiones tomadas, distinguiendo un fraude real de un falso positivo por certificado.

Una respuesta incorrecta en el punto 1 o en el punto 3, o abrir voluntariamente un enlace fraudulento durante la práctica, supone la no superación del criterio.
